Map it. Plan it. Ship it.

n-dx reads the repo you already have, turns what it finds into a living plan stored in git, and has an agent work that plan one task at a time — in your terminal, with Claude Code or Codex.

Free play. No seat, no subscription, no token markup. n-dx runs on the Claude Code or Codex plan you already pay for — or on a local model.

01IntroductionScroll ↓

AI agents write code fast. Then they forget what they built, why they built it, and what comes next. n-dx gives them a map of the codebase, a plan that lives in git, and a loop that works through it.

02Problems

Your agent is fast.
It is also lost.

Chat-driven coding works at the file level. Real repos fail at the project level — the part no prompt carries from one session to the next.

  1. Blind01

    It can't see the architecture

    Agents read files one at a time. Zones, boundaries, and the import graph stay invisible, so every change is a local guess.

  2. Amnesiac02

    Every session starts from zero

    Context evaporates between runs. You re-explain the repo, the goal, and what's already done — again.

  3. Drift03

    The plan and the code disagree

    A spec written up front is stale the week you ship. Nobody re-derives it from what's actually in the tree.

  4. Unaccounted04

    Nothing records what ran

    Which task, which model, how many tokens, which files changed? A chat log can't answer that.

03The loop

One loop.
Four levels.

Run it once to get started. Run it again to stay current. Each level feeds the next, and the PRD keeps score.

  1. 1-1Analyze
  2. 1-2Plan
  3. 1-3Work
  4. 1-4See

    04ToolsPress start

    Choose your tool.
    Or take all three.

    Three packages behind one command, ndx. Each works alone; together they close the loop.

    P1The scanner

    sourcevision

    Static analysis that turns a repo into context an agent can use.

    • File inventory with content hashes
    • AST import graph and cycle detection
    • Louvain zones with cohesion and coupling
    • React / Preact component and route catalog
    • CONTEXT.md · llms.txt · zones.json
    10 MCP toolsndx analyze .
    P2The planner

    rex

    A PRD that lives in your repo as a folder of markdown.

    • Epic → feature → task → subtask
    • Priorities, blockers, acceptance criteria
    • Proposals from findings, or plain-English ndx add
    • Acceptance criteria mapped to tests
    • Sync to Notion for non-engineers
    19 MCP toolsndx recommend .
    P3The builder

    hench

    An agent loop that works the plan, one task at a time.

    • Picks the next unblocked task by priority
    • Briefs with PRD and codebase context
    • Claude Code, Codex, Gemini, or local models
    • Allowlisted commands, blocked paths, rate limits
    • Full transcripts in .hench/runs/
    50 turn cap (default)ndx work .
    05Features

    Built for the repo
    you already have.

    Not a demo on a blank folder. The details that matter once an agent is committing to a codebase people depend on.

    A

    The plan lives in git

    Every PRD item is a folder under .rex/prd_tree/ with an index.md. Review a plan change like any other diff.

    
      
    

      
    
        
    
          B
          
    Parallel worktrees
    
          
    Each git worktree claims its own task, and the others skip it. Run several agents on one repo without collisions.
    
        
    
        
      
    

      
    
        
    
          C
          
    29 MCP tools
    
          
    ndx init writes .mcp.json and .codex/config.toml. Your agent can read and update the PRD directly.
    
        
    
        
    
      
    

      
    
        
    
          D
          
    Every token on the tab
    
          
    Token usage rolls up to the PRD item that spent it. ndx usage turns it into a cost estimate.
    
        
    
        
      
    

      
    
        
    
          E
          
    Self-heal
    
          
    Re-analyze, recommend, execute, acknowledge — N times over. Fixed findings don't come back as new.
    
          
    ndx self-heal 3 .
    
        
    
        
    
      
    

      
    
        
    
          F
          
    A second opinion
    
          
    One vendor builds; the other reviews by running your tests. ndx pair-programming — or ndx bicker.
    
        
    
        
    
          
          LGTM?
          Tests say no.
          
        
    
      
    

      
    
        
    
          G
          
    Guardrails, not vibes
    
          
    An allowlist of commands. No git push, reset, or rebase. .git and .rex are off-limits. 60 commands a minute. The agent can't edit its own guard config.
    
        
    
        
      
    

      
    
        
    
          H
          
    Commits that explain themselves
    
          
    Hench signs its work with git trailers: status, vendor, model, run, and a permalink to the PRD item.
    
        
    

    feat(editor): auto-save notes on idle

    06Use cases
    
    
    
      
    Made for the people
    in the codebase.
    
    
    
    
    
      
      
        
    1. 
          
      A prototype became the product. n-dx finds the patterns and anti-patterns across zones, turns them into a prioritized backlog, and works it down with guardrails on.
      2. 
        
    2. 
          
      New to a repo, human or agent? One analysis gives you the zones, the hubs, the cycles, and a CONTEXT.md that reads in minutes instead of days.
      3. 
        
    3. 
          
      Describe what to build in plain English. Rex structures it into epics, tasks, and acceptance criteria; hench executes from that structure, and every run traces back to the spec.
      4. 
        
    4. 
          
      The code never stops changing, so the plan can't either. Self-heal re-derives findings from the tree and acknowledges what's fixed, so the PRD stays true without manual tracking.
      5. 
        
    5. 
          
      A shared source of truth without another planning tool. ndx ci checks PRD health on every push; Notion sync shows progress to people who never open a terminal.
      6.
